# 台湾周会销售数据更新 SOP

本 SOP 用于后续台湾周会正式飞书文档更新。正式文档可能不再保留红色需求说明，执行时仍按本文档固定流程，从「打卡数据」开始，按模板顺序更新到「人均分发观测（台湾商务）」为止。

## 一、执行原则

- 只操作当前模块对应的飞书嵌入表格和对应总结区域，不改变用户原文档内容顺序。
- 每个模块必须按模板顺序逐个处理，禁止跨模块写入、插入或删除内容。
- 以正式飞书文档中的模块标题和嵌入表格顺序重新识别 sheet id；历史 sheet id 只作参考。
- 表头、合并单元格、颜色、边框、数字格式、日期格式、百分比格式尽量保持 Smartbi 导出和模板原样。
- 写入后必须清理多余空白行/格；能删除行时删除行，不只留下空白尾行。
- 数量列不能误设为百分比；百分比列底层值保留为小数并显示为百分比。
- 不出现绿色小角标或文本数字问题。
- 每个模块写完后读回关键区域，确认数据、表头、格式、行数、尾部无空白都正确。

## 二、通用输入与工具

- 用户后续通常只提供正式飞书文档链接。
- Smartbi 地址：`https://bi.61info.cn/smartbi/vision`
- Smartbi CLI 目录：`D:\工作\曾晓芳\smartbi-data-cli-redacted-20260520`
- Smartbi 密码不写入 SOP 或仓库；执行时从环境变量或用户当次授权读取。
- 飞书写入使用飞书 CLI；宽表、特殊表头、包含 `<`/`>` 的表头使用 Node 直接调用 CLI，避免 shell 解析问题。
- BI/Smartbi 下载任务优先使用 Chrome Browser Use 后端或 Smartbi CLI，避免 Codex 内置浏览器下载受限。

## 三、日期口径

- 执行数据更新的前一天作为主要结束日期。
- 开始时间若模板原需求为「默认」，则 Smartbi 保持默认开始时间。
- 月度类模块通常从当月 1 日到执行日前一天。
- 周期类模块按 Smartbi 导出结果保留所有批次，不手动删最新批次，除非用户明确要求。

## 五、写入与格式检查清单

每个模块写入后都执行以下检查：

- 读取表头区域，确认表头没有错位、乱码或丢失。
- 读取数据开头、中间关键行、尾部最后 3-5 行。
- 确认当前模块行数与导出有效行数一致。
- 确认尾部没有多余空白行；如存在多余行，删除或压缩。
- 确认整数列不是百分比格式。
- 确认百分比列不是普通数字格式。
- 确认小数列显示位数符合导出/模板。
- 确认合并单元格恢复正确。
- 确认颜色规则正确，尤其 BY CC 环比和达成率。
- 确认总结/结论区域按模块要求更新。
- 确认只改了当前模块，没有影响上一个或下一个模块。

## 六、后续自动执行方式

当用户后续只发送正式台湾周会飞书文档链接时，按以下方式执行：

1. 解析文档，定位销售部分从「打卡数据」到「人均分发观测（台湾商务）」的模块和嵌入表格。
2. 按本文档模块顺序逐个导出 Smartbi 数据。
3. 对每个模块生成写入矩阵，匹配模板表头和导出格式。
4. 写入当前模块并立刻读回校验。
5. 修正格式、颜色、合并、空白尾行和总结。
6. 全部完成后，向用户简要说明已更新模块、主要校验结果和残留风险。
